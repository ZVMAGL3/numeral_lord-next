# PvP 与 Mod 联调清单

## 当前联机模型

`apps/server` 提供薄的 Colyseus `pvp` 房间。后端维护房间号、成员/观战身份、地图位、准备状态、房主、断线窗口和消息广播；房主客户端持有权威 `GameState`，执行 `game-core` 后广播 `host-snapshot`。其他参战客户端发送 `player-intent`，观战者只能接收快照。发生冲突时，以房主快照为准。

地图玩家位和房间成员是两个独立概念：

- `mapPlayerCount` 来自地图，限制同一局最多有多少参战者。
- 准备房间没有可配置的成员人数。加入几人就显示几人，列表始终先排参战者、后排观战者。
- 观战者不占地图位；服务端当前 64 连接上限只是防止传输资源失控，不是地图或房间规则。
- 开局后通过房间号加入的成员固定为观战者，并请求房主当前快照。

## 启动方式

先启动服务端：

```powershell
corepack pnpm --filter @numeral-lord/server start
```

再启动网页：

```powershell
corepack pnpm dev:web
```

打开 `http://127.0.0.1:5173/`。主页有“联机大厅 / 地图配置 / 创意工坊”三个同级入口，不显示地图预览。首次访问会自动生成名字并写入 `localStorage`；临时房间身份在每个标签页的 `sessionStorage` 中独立保存，刷新同一标签页可恢复座位。选择“联机大厅”后点击“创建新房间”，其余玩家输入房间号，或直接打开邀请链接。远程中继可用 `?relay=ws://服务器地址:2567` 指定；`room` 与 `relay` 查询参数可以同时保留。HTTPS 页面必须使用 `wss://`。

房间页右上角有“连接日志”。若玩家突然掉线或卡在“正在同步棋盘”，先在两个玩家的标签页分别复制日志；刷新当前标签页后日志仍会保留。日志中的 `socket.closed.code`、`connect.failed`、`room.host` 和 `snapshot.received` 可区分连接关闭与接管后的同步失败。再让服务器管理员提供相同时间段的 `journalctl -u numeral-lord.service --since '时间' --no-pager`；若服务重启，当前内存房间号会失效，无法仅靠客户端重连恢复。

## 准备房间验收

### 1. 主页、地图库与地图预览

1. 清除站点的 `numeral-lord.player-name` 后刷新，确认主页自动生成非空名字。
2. 确认主页仅有名字输入和两个等权入口，不出现地图缩略图或大段介绍文案；修改名字并点击“联机大厅”，刷新后确认仍使用该名字，房间成员列表也应显示此名字。
3. 留空或只输入空格后进入“联机大厅”，确认页面重新生成名字；输入超过 24 个字符时只保留前 24 个字符。
4. 打开“地图配置”，确认内置首图名为「昏晓」，能预览、查看并复制其 JSON 地图码；页面只提供导入地图码，不应出现可视化编辑控件。
5. 把有效且新 ID 的地图码粘贴导入，确认出现在本机地图库；无效码给出可理解的错误，刷新后自定义地图仍在。内置「昏晓」不能从列表移除。
6. 从地图库、房间入口、准备房间或对局返回主页；离开联网房间后 URL 不再带旧 `room` 参数，刷新也不应重新加入旧房间。直接打开带 `room` 的邀请链接时仍应绕过主页进入指定房间。
7. 进入准备房间，确认右上角显示当前地图的真实地形、初始单位数值、玩家颜色与贴图。
8. 地图预览应由与对局相同的 `HexBoard` 和 `GameState` 渲染，但采用只读紧凑模式：点击不能选中或操作单位，也不显示可行动脉冲、选中框或合法目标框。

这张预览不是静态截图。地图数据或渲染器变化时，预览与正式棋盘应同步更新；部署到子路径时它也应使用同一套 `BASE_URL` 贴图地址。

### 1.1 房主准备阶段选图

1. 房主先在地图配置页导入另一张不同玩家位的地图，再创建房间，在准备阶段切换到该地图。
2. 核对所有成员看到相同地图名称、玩家位、地形和初始单位预览；没有本机导入该地图的访客也应看到正确地图。
3. 先让参战者准备，再切换地图，确认准备状态全部清除；缩减玩家位时，超出新地图玩家位的成员转为观战。
4. 用所选地图开局，并在另一个标签晚加入观战，确认正式棋盘和快照使用同一地图码。

### 2. 创建、加入与成员排序

1. 创建房间，确认创建者成为房主并获得房间号。
2. 用房间号连续加入多名成员。默认地图「昏晓」只有 2 个玩家位；前两名默认参战，之后加入者自动观战。
3. 把任意参战者切到观战位，再把观战者切到空出的玩家位。
4. 确认列表在每次调整后仍是参战者在前、观战者在后，且所有成员都可见。

固定位置模式下，成员可选择具体空位，房主也可代为调整；房主把成员调到已占位置时，会交换或移交原位置。观战者不显示准备按钮，也不会计入准备进度。

### 3. 固定位置与随机位置

- 固定位置：参战者必须占据唯一的具体地图位，位置直接映射为 `player-1`、`player-2` 等地图玩家 ID。
- 随机位置：成员只选择“参战”或“观战”；开局时服务端从全部地图位中随机抽取位置分给参战者。因此在未坐满地图时，未使用的位置也可能位于参战者之间。
- 在两种模式之间切换时，服务端保留不超过地图位数量的现有参战者，并重新整理位置；所有人的准备状态会清除。

### 4. 开局门槛与空地图位

1. 只保留一名参战者，其余成员设为观战。
2. 让这名参战者准备，确认房间可以自动开局，不要求坐满地图的所有玩家位。
3. 再用两名参战者测试：一人未准备时不能开局；所有参战者都在线且准备后立即开局。
4. 观战者无须准备，且不影响开局。

开局载入地图时，只保留已分配玩家位的初始单位；没有参战者的位置会清空全部初始单位，规则上相当于开局已无军队，之后轮转会跳过该玩家。房间层不会因为空位自行判胜；地图选择的胜负模块仍会在 `startMatch` 时运行。因此，演示地图启用了“最后存活队伍获胜”，单人开局会立即结算，这是地图规则而不是大厅人数限制。没有该条件的目标型地图可以在空位存在时正常继续。

### 5. 房间设置

只有房主可修改以下设置；任一修改都会取消全部准备状态：

- 友方伤害：关闭时同队单位不能互相攻击，开启时允许。
- 步时：一名玩家的行动与加点共用一次倒计时，移动、攻击、加点都不刷新；`0` 表示不限时。行动结束时加点至少保留 2 秒；加点阶段步时耗尽则强制轮到下一玩家。
- 局时：每位玩家各自累计耗时，只在其行动/加点期间扣减；`0` 表示不限时。某玩家局时耗尽会强制结束其当前回合，此后该玩家每回合仍有 2 秒行动与至少 2 秒加点。
- 随机位置与次序：关闭时使用固定地图位，开启时开局随机分配。

当前输入约束为步时 `0` 或 10–300 秒，局时 `0` 或 1–180 分钟；两者均非 0 时，步时不得超过局时换算的秒数。拒绝无效设置时保留原设置及准备状态。

## 对局中与晚加入观战验收

1. 让至少两名参战者准备并开始对局；确认只有当前地图玩家能操作，非当前玩家的棋盘操作被锁定。
2. 复制房间号，在第三个标签或另一台设备中途加入。确认它直接显示当前棋盘和计时，而不会回到准备房间，也不会获得地图位。
3. 在晚加入标签尝试移动、攻击、加点和结束阶段，确认均不能提交；房主继续行动后，观战画面应随快照更新。
4. 让房主离开，确认下一位在线成员成为房主并继续广播。若新房主是观战者，他仍不能以玩家身份行动，但负责接收参战命令、执行规则并广播快照。
5. 在 Colyseus 重连窗口内恢复连接，确认原成员状态能够继续；超过窗口后按离开处理。

`room-sync` 用于补发身份和房间状态；服务端会缓存最近一次房主快照并定向发给中途加入者。刷新后凭本机账户标识认回原座位，不会新增同名观战者。当前快照只在房间进程内保存，事件日志、持久化与跨进程恢复仍未实现。

## Mod 与静态资源验收

- 内置「昏晓」显式安装 `mod-oil-field`；油田位于行列 `[2,6]`、`[6,1]`，视觉上使用棕色底、金色边框与旧版油田贴图。
- 所选完整地图码由房间同步，访客无需先导入；所有客户端仍须具备该地图所用的核心目录和 Mod catalog。中继不安装 Mod，也不执行 Mod 规则。
- 本地开发时贴图地址为 `/legacy/…`。执行 `corepack pnpm --filter @numeral-lord/web build:deploy` 后，Vite `BASE_URL` 为 `/numeral-lord-play/`，贴图应请求 `/numeral-lord-play/legacy/TS0.png` 等子路径，而不是站点根目录 `/legacy/…`。
- 即使可选贴图加载失败，棋盘仍应显示基础色并可操作；控制台可以给出资源警告，但不能让规则棋盘消失。
- 新房间状态包含所选地图的 `requiredTerrainModIds`、每位成员的 `missingModIds`，以及房主的 `roomModSettings`；缺少 Mod 的参战者不能准备，服务端也不会让其开局。
- 油田 `incomePerTurn` 默认 2，地图作者可在地图码 `modSettings` 中改为 0～20，房主可在准备房间的“地块 Mod 设置”覆盖。修改会清除准备状态，换地图清空房主覆盖值；返回准备房间后保留本房间覆盖值。
- 公网工坊目前只读；社区地块 Mod 的源码归档可以预览/下载，但不会自动安装或执行。保存地图码不代表依赖已安装。

## 独立公网测试入口

当前测试页为 `http://39.107.250.161/numeral-lord-play-stage/`，与原公网入口使用不同的服务进程、端口和网页目录。更新测试页只会重启 `numeral-lord-staging.service`；正式 `numeral-lord.service` 不受影响。测试页的工坊可以列出作品，但暂不接受匿名发布。

从仓库根目录可运行下面两个只创建临时房间的检查：

```powershell
$env:PVP_SMOKE_CHECK_RESET = '1'
pnpm --filter @numeral-lord/web exec node scripts/public-pvp-smoke.mjs
pnpm --filter @numeral-lord/web exec node scripts/public-workshop-smoke.mjs
```

第一个脚本验证缺失 Mod 不能准备、报告已安装后可准备、房主油田参数同步到双方、超过旧 4 KiB 限制的快照能传输，以及房主结束对局后双方回准备房间。第二个脚本验证工坊房间可连接、列表格式正确且匿名发布被拒。真人双端的行动、刷新重连、房主移交和视觉效果仍需继续验收。
