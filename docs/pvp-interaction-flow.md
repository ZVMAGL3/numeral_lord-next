# PvP 交互与状态边界

联网对局把状态分成三类，不能相互混用。

## 1. 对局状态与恢复源

`GameState` 是规则状态：单位、地块、点数、行动阶段、反击次数等。离线和联网玩家都先在本机调用 `game-core`，立即更新棋盘；随后以 `player-intent` 异步转发命令。房主也会执行其他成员的命令并发送缓存快照。房主快照用于新加入/重连客户端和冲突修复；普通操作不等待快照后才在本机显示。该设计提升输入响应，但中继仍不是服务端权威反作弊模型。

## 2. 本地交互状态

`useBoardInteraction` 管理当前浏览器自己的 `selectedUnitId`、来源格、合法目的格和红/白反击提示。这些是未提交的行动意图，可能暴露计划，因此不属于 `GameState`，也不通过房间服务转发。对手和观战者只能看到已提交并同步的棋盘，不能看到行动者的选中单位或下一步位置。

红框/白框只对本地已选中的攻击单位计算，并且只标在该单位当前合法攻击的占据格上。取消选择后，本地的选中、可达格和红/白框一起清空。

## 3. 本地先响应与命令修复

每位玩家都先执行自己的命令、提交本地状态和棋谱，再异步发送带序号的 `player-intent`。其他客户端收到后用相同引擎依次重放；若命令历史或当前行动者冲突，会清除旧预览并向房主请求状态修复。普通房主快照只是可重发的状态缓存，不是客机每次操作的确认信号。规则拒绝仍发生在发出命令前，因此本机非法操作不会提交。

## 交互顺序

1. 点击己方可行动单位：校验当前行动权和单位状态，在本地选中并显示本地预览。
2. 点击本地合法格：立即清除预览并由共享引擎更新本机状态；联网时同时向房间异步发送命令。房主在同一条序列中复算并缓存快照。
3. 远端收到命令：重放相同命令并提交；如果历史序号或行动者冲突，触发快照恢复，而不是把普通快照当作本机提交的确认。
4. 点击棋盘内非合法格或棋盘外空白：清除当前浏览器的预览，不改变对局。
5. 加点、结束阶段、返回准备房间、断线或收到非本人的棋盘更新：清除本地旧选择；本人动作的可继续行动单位由本地规则结果 `continuation` 决定。

代码对应：`apps/web/src/board/board-interaction.ts` 管理私有交互状态，`apps/web/src/rooms/command-sync.ts` 管理命令历史与序号，`apps/web/src/app/app-runtime.ts` 负责本地先响应和修复流程，`packages/game-core/src/engine.ts` 是共享规则内核，`apps/server/src/index.ts` 校验并转发有限形状的命令、管理房间和快照缓存。
