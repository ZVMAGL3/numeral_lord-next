# Numeral Lord Next

新版多人六边形战棋平台。项目采用 TypeScript 单仓库：客户端负责本地即时规则与渲染，服务端负责创建/加入房间、准备状态、地图位分配、断线重连和低延迟数据中继；联网对局由房主广播权威快照。

## 工作区

- `apps/web`：Vue 用户界面、准备房间与 PixiJS 棋盘渲染器。
- `apps/server`：房间号、成员/观战者、断线重连、房主权威快照中继与创意工坊作品存储。
- `packages/game-core`：不依赖框架或网络的确定性规则内核，以及共享的大厅协议类型。
- `packages/game-sdk`：地图与 Mod 作者使用的稳定扩展 API。
- `packages/content-schema`：内容包、地图和资源清单的校验模型。
- `docs`：游戏规则、联调清单和架构决策。

详细边界见 [架构基线](docs/architecture-baseline.md)，公网目录、服务与子路径构建说明见 [部署说明](docs/deployment.md)。

## 本地运行

先安装依赖，再分别启动中继和网页：

```powershell
corepack pnpm install
corepack pnpm dev:server
```

另开一个终端：

```powershell
corepack pnpm dev:web
```

打开 `http://127.0.0.1:5173/` 后，主页有“联机大厅”“地图配置”“创意工坊”三个同级入口。首次访问会随机生成名字并保存在浏览器 `localStorage`；临时房间身份保存在当前标签页的 `sessionStorage`，刷新可续位，不同标签页不会互相接管。开发页默认连接本机 `:2567`；连接其他中继可加 `?relay=ws://服务器:2567`。邀请链接使用 `?room=房间号` 直接加入指定房间。房间页的“连接日志”可复制最近的断线码、重连和快照事件，刷新后仍保留在当前标签页。

“地图配置”中内置的第一张地图是「昏晓」。目前可粘贴 JSON 地图码导入自己的地图，预览、查看并复制地图码；暂不提供可视化编辑。主页不显示地图预览，地图库和准备房间提供预览。自定义地图只保存在当前浏览器。房主可在准备房间选择本机已有地图，房间会把所选完整地图码同步给其他成员，因此其他玩家不必事先导入。

创意工坊分“地块 Mod”和“地图 Mod”。地图作品只是可分享的地图码，可预览并保存到本机地图配置，不需要安装地图包；地图码的 `requiredTerrainModIds` 列明所需地块 Mod。缺少依赖时仍可收藏地图码，但不能在房间中开局。上传的地块 Mod 源码仅作为文本供预览，不会自动安装或执行；当前只有随客户端构建的油田 Mod 可用于实际对局。在线工坊暂为匿名试验服务，公开部署前还需账号鉴权、审核和更强的限流。

规则包不依赖页面：浏览器使用 `@numeral-lord/game-core`，Node 服务端或训练程序使用编译后的 `@numeral-lord/game-core/node`。房主客户端和 AI 模拟调用同一套状态与命令规则；当前 PvP 中继只传递成员状态、命令和房主快照，不在服务端重复执行棋盘规则。

## 房间、地图位与观战

- 地图声明自己的玩家位数量；准备房间不再设置“房间人数”。每位加入者都会出现在成员列表中，参战者排在前面，观战者排在后面。
- 准备房间右上角直接复用只读紧凑模式的 `HexBoard`，按真实 `GameState`、地形、初始单位与贴图绘制地图预览，不使用静态截图。
- 房主可在准备阶段切换地图。地图名称、玩家位和预览会同步更新；换图会取消所有人的准备状态，超出新地图玩家位的成员转为观战。
- 观战者不占地图玩家位，也不受地图玩家位数量限制。当前服务端另有 64 个并发连接的传输安全上限，它不是游戏人数设置。
- 固定位置模式下，参战者选择具体地图位；房主可以调整成员位置。随机位置模式下只选择“参战/观战”，开局时从地图玩家位中随机分配参战者的位置与次序。
- 只要至少一人参战，并且所有参战者都在线且已准备，就会自动开局；观战者无需准备。未分配给参战者的地图位会清空其初始单位，规则上相当于该玩家开局已无军队，并会被后续回合跳过。
- 房主可设置友方伤害、步时、局时和固定/随机位置。修改房间设置会取消所有参战者的准备状态。
- 对局开始后仍可凭同一房间号加入；新成员直接成为观战者，向房主取得当前快照，不能提交移动、攻击或加点。

“至少一名参战者即可开局”只是不再强制坐满地图位。胜负仍完全由地图启用的条件模块决定；例如启用“仅剩一队获胜”的地图，单人开局可能立即结算，而其他目标型地图可以继续进行。

## PvP / Mod 联调

房主本地执行来自参战者的命令并广播快照，冲突以房主快照为准。房主离开后，房间会把下一位在线成员提升为房主。完整验收场景见 [PvP 与 Mod 联调清单](docs/pvp-testing.md)。

意外断线时客户端会有限次数自动重连，服务端会立即移交房主并保留断线玩家的座位供原标签页恢复。对局和房间仍只在内存：服务进程重启会清空所有房间；排查断线时请同时提供页面“连接日志”和服务端 `journalctl -u numeral-lord.service` 中对应时段的记录。

房间会同步所选完整地图码，其他客户端无须先在本机地图库保存该地图；但所有客户端仍须安装地图所用的核心目录和 Mod catalog。中继不会安装 Mod，也不会执行地图规则。油田不是核心地形，而是 `packages/oil-field-mod/` 中的可选 Mod；装配方式见 [Mod 示例](docs/mod-example.md)。

部署到 `/numeral-lord-play/` 时使用 `corepack pnpm --filter @numeral-lord/web build:deploy`。棋盘贴图通过 Vite 的 `BASE_URL` 生成地址，因此会从 `/numeral-lord-play/legacy/…` 加载，而不是错误地请求站点根目录 `/legacy/…`。
