## 工作方式与预算

- 使用一个执行子 agent，主 agent 负责阶段审查，避免多个实现者同时写同一批文件。
- 每个工作片段约 15 分钟，持续完成有用工作；片段结束写进度与下一步，不为耗 token 做空循环。
- 用户截图的当前 5 小时额度约剩 10%，这不是可读取的精确 token 数，不将周额度自动视为本次预算。不启动付费 API、不购买额度。
- 调度检查只推进未完成阶段，不重复启动训练，不并行跑多套 GPU 实验。若触及额度限制，记录可恢复状态；不假定额度已刷新，也不声称能精确耗尽最后一个 token。
- 使用率耗尽与本地训练不是同一开关：已启动的受控训练可以独立写日志/检查点，不能依赖 agent 一直在线才能保存结果。
- 外部定时续跑要以实际创建成功的调度任务为准；只有循环脚本或一条回复不代表 agent 会自动醒来。

## 不变量

- 不改昏晓初局、地形、落点、初始兵力、队伍或正常胜负条件。
- 不重新加入十回合结算、兵力比例结算、进攻奖励或强制按回合判胜。
- 游戏规则仍通过本地共享内核执行。旧正常规则数据可作状态/终局监督；旧浅策略标签不自动视为正确答案。
- 第 20 代检查点与原始棋谱只读保存，candidate 与 champion 分开命名，不覆盖旧权重。
- 首轮默认最多 8 个自博弈 worker，验证内存和速度后可到 16；预留至少约 5 GiB 系统可用内存。一次只运行一个训练闭环。

## 阶段一：修复可学习性与训练一致性

1. 重跑 `python/audit_checkpoint.py`，保留基线 JSON，确认旧模型上下文抵消与价值诊断可复现。
2. 优先复用已有 `hex_model.py` 的六邻接、LayerNorm、src/dst gather，建立健康初始化的空间网络候选。保留共享长期价值；阶段拆头只在接口需要时引入，不把它当作已证实的提升原因。
3. 对比旧 MLP，确认候选评分显式依赖源/目标空间上下文，不继承旧 encoder 的巨大激活。训练记录激活、logit、价值饱和与梯度等诊断。不得靠给输出加入噪声制造“上下文敏感”。
4. 统一样本权重路径，保证用户要求的局长/短胜权重实际作用于所选训练器；记录真实配置。无局长权重只可作为明确标注的对照。
5. candidate、champion、metrics 使用各自不混淆的路径；淘汰候选也保留，明确冠军实际参数哈希。
6. 完成必要单元验证与小样本拟合，检查错误高置信价值仍有梯度、两阶段输入/候选合法且 finite。诊断本身不能替代棋力验证。

验收：相关 Python 测试、`pnpm ai:typecheck` 和 `pnpm ai:test` 通过；模型健康检查通过；新检查点与环境 fingerprint 一致。若不通过，不扩量采局。

## 阶段二：实际启动训练并检查闭环

1. 选择当前正常规则、已自然结束的完整对局，按 gameId 做训练/验证分离；流式或有限样本载入，避免一次载入所有历史数据。
2. 先用最多约 4,096–16,384 条代表性局面做空间模型热启动和数值检查。旧策略分布仅作低权重热启动或对照，不把拟合旧模型当作学会好棋。
3. 用新空间模型完成 2–4 局无界面 smoke self-play，正常结束才记录真实胜负；计算预算耗尽记录截断，不伪造结果。
4. 运行受控的短 XPU 训练段，验证产生新权重、训练日志、metrics、棋谱和续训入口。设备检测失败先修环境，不静默用 CPU 跑整晚。
5. 验证后启动首批 100–200 局试验，输出新命名目录、PID、参数、资源与当前阶段。训练无需可视化；沿用现有棋谱保存与回放接口。

验收：确实存在运行进程或已完成的训练产物，不能仅以“脚本写好了”报告已开始训练；同时报告真实启动的是热启动、采局还是梯度更新。

## 阶段三：让搜索提供增量信息

1. 从合法旧棋谱提取一小组可重放局面，覆盖前线投点、海路、供电、据点威胁与防守。可证明的战术事实与战略偏好分开，不把启发式分数当最佳答案。
2. 同一健康模型以固定实际模拟次数 16/64/256 做曲线；再单独做等墙钟对照。记录完成阶段/换人深度、合法分支覆盖和实际节点数。
3. 先实现有界评估缓存/子树复用；验证 key 包含完整规则相关信息。等价增援 AB/BA 合并单独验证，不粗暴按棋盘位置合并不同失活/资源状态。
4. 搜索开始比较若干完整增援分配及后续应对，保持底层合法动作探索与逐原子规则验证，不硬编码角落无效或必须进攻。
5. 搜索必须在战术或后续对局中优于原策略，才能作为更强老师。否则先修搜索，不继续生成千盘弱标签。

## 阶段四：专家迭代与扩量

1. 选择约 2,000 个争议/代表性局面重新搜索，生成较可靠策略目标，保持预算上限与训练/验证隔离。
2. 比较空间模型和健康交互 MLP；一次只变一个主要因素。阶段双头、Gumbel、replay 窗口等后续独立比较。
3. 参考 KataGo 分配轻重搜索预算，先实测比例/收益，不照抄围棋目数效用或宣称相同加速倍数。
4. 先用 16–32 对换边对局筛选；正式晋级预先约定局数，或采用正确顺序检验。原始两席位成绩、直接对战成绩与用户后手偏好权重分别报告。
5. 只有表现改善才扩大到每节点 1,000 局；不把代数、GPU 利用率或 loss 下降单独写成棋力提升。
