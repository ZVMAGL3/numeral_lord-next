# PvP 交互与状态边界

联网对局把状态分成三类，不能相互混用。

## 1. 权威棋盘状态

`GameState` 是规则状态：单位、地块、点数、行动阶段、反击次数等。离线时由本地 `game-core` 命令更新；联网时玩家发 `player-intent`，房主调用同一个 `game-core` 验证并更新，然后通过 `host-snapshot` 广播完整结果。客机不先改棋盘，收到权威快照后才确认行动。

## 2. 本地交互状态

`useBoardInteraction` 管理当前浏览器自己的 `selectedUnitId`、来源格、合法目的格和红/白反击提示。这些是未提交的行动意图，可能暴露计划，因此不属于 `GameState`，也不通过房间服务转发。对手和观战者只能看到已提交并同步的棋盘，不能看到行动者的选中单位或下一步位置。

红框/白框只对本地已选中的攻击单位计算，并且只标在该单位当前合法攻击的占据格上。取消选择后，本地的选中、可达格和红/白框一起清空。

## 3. 客机的待确认行动

客机提交联网行动、加点或结束阶段时，`usePendingCommand` 只允许一个命令在途，保存命令 ID、预期序号和成功后的本地处理方式；它不代表棋盘已变化。待确认期间棋盘操作锁定，也不会提前记棋谱。房主接受命令后，客机按命令 ID 匹配快照：成功时再记棋谱；行动命令还会按权威结果继续选中可继续行动的单位；失败时解锁、清选并显示房主给出的原因。没有匹配待确认命令的外部棋盘更新会清除本地旧选中，避免把旧预览套到新棋盘上。

## 交互顺序

1. 点击己方可行动单位：校验当前行动权和单位状态，在本地选中并显示本地预览。
2. 点击本地合法格：立即清除预览。离线端执行命令；客机发送命令并等待房主；房主执行后发布新快照。
3. 收到权威结果：客机按命令 ID 确认/拒绝并更新棋谱；仅当结果明确给出可继续行动单位时，才创建新的本地选中。
4. 点击棋盘内非合法格或棋盘外空白：清除当前浏览器的预览，不改变对局。
5. 加点、结束阶段、返回准备房间、断线或收到非本人的棋盘更新：清除本地旧选择；若本人行动得到房主确认且仍可继续行动，再按快照提供的 continuation 重建选择。

代码对应：`apps/web/src/board-interaction.ts` 管理私有交互状态，`apps/web/src/pending-command.ts` 管理客机命令生命周期，`apps/web/src/App.vue` 负责接线，`packages/game-core/src/engine.ts` 是前后端共用的规则权威，`apps/server/src/index.ts` 只转发行动请求和权威快照。
