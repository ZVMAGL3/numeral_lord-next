# 移动端点击棋盘闪烁

## 现象

手机浏览器中点击对局棋盘时，画面会短暂闪一下；点击其他界面控件没有相同现象。用户反馈使用手机自带浏览器和 Chrome 都能复现。拖动平移和双指缩放正常。

## 排查结论

连接日志里的 `board.input-timing` 记录显示，出现闪烁的点击前后 `sequence` 不变，`boardDrawMs` 与 `interactionDrawMs` 为 `null`，单位格没有重建。这说明该点击没有触发游戏状态推进或 Pixi 棋盘/交互层重绘，因而不支持“棋盘被完整重画导致闪烁”这一解释。

结合“只有棋盘点击时发生”以及修改后的用户反馈（“好像没有了”），原因最可能是移动浏览器在 Pixi 画布点击时显示了浏览器原生点按高亮，而不是游戏绘制闪烁。棋盘容器是这条触摸输入路径独有的 DOM 区域；旧逻辑还会在指针移动/抬起时设置 `cursor: pointer`，没有区分鼠标与触摸。日志无法单独证明浏览器高亮的内部触发条件，因此将其记录为高概率根因，而不是声称已从浏览器内部跟踪确认。

## 修复

在 `apps/web/src/components/HexBoard.vue` 中做了两项局部调整：

- 仅鼠标指针在格子上时才把光标设为 `pointer`；触摸指针保持抓手光标，不再套用鼠标的悬停反馈。
- 对 `.board-canvas` 设置 `-webkit-tap-highlight-color: transparent`，关闭浏览器在该画布区域的原生点按高亮。

没有修改游戏规则、Pixi 图层、棋盘状态或整盘绘制流程。桌面鼠标提示与现有触摸拖动、缩放行为保持不变。

## 验证记录

- 2026-09-29：正式站页面、含新点按高亮规则的 CSS 资源和 relay 健康检查均返回 HTTP 200，修复已部署。
- 2026-09-30：用户反馈点击棋盘“好像没有了”。这与上述定位和修复相符；由于没有连接用户手机进行远程实机采集，仍以用户端实际体验作为最终验证。

## 后续排查提示

若再次出现类似现象，先确认点击前后的 `sequence`、`boardDrawMs`、`interactionDrawMs` 和重建计数。若状态未变且绘制指标为空，应优先检查画布 DOM 输入反馈和浏览器合成层，不要先改游戏规则或增加补偿性重绘。
